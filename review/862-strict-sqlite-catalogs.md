# Validate the SQLite schema before opening protected stores

Design for [#862](https://github.com/rock3r/remozio/issues/862), based on main `062e9ad509e6af7eeb006e9f0426d423de00a51b`. The three stores open SQLite under a protected lease and disable trusted schema. They still need to admit only the schema produced by the supported initialization and migration paths. This is a source review.

## Current open paths

- **JournalDatabase.** The initializer opens the protected file and validates it before initialization or migration. It checks the application ID, format, identity row and scope, and probes expected columns. For format 19 it also checks recovery storage and the tier-specific table set. The continuity digest uses that table set for formats 12–19, but the catalog query selects only tables. The digest then reads column names and row values. It gives no evidence about triggers, views, or index definitions. [Open and checks](../macos/core/Sources/RemozioCore/JournalDatabase.swift#L78-L120), [identity and columns](../macos/core/Sources/RemozioCore/JournalDatabase.swift#L432-L495), [catalog and digest](../macos/core/Sources/RemozioCore/JournalContinuityDigest.swift#L24-L67).
- **GatewayDatabase.** The initializer opens the Gateway file for ordinary writes or read-only update health. It checks the application ID, version, registration identity, head, expected columns, and capacity. Ordinary startup can then migrate a legacy store and clear retained process-local state. The read-only health path also calls `quick_check`. Neither path compares the application schema with the expected catalog. [Open, migration and cleanup](../macos/core/Sources/RemozioCore/GatewayDatabase.swift#L89-L132), [health checks](../macos/core/Sources/RemozioCore/GatewayDatabase.swift#L139-L152), [identity and columns](../macos/core/Sources/RemozioCore/GatewayDatabase.swift#L1011-L1053).
- **ContinuityStore.** The initializer opens the separate checkpoint file and accepts versions 1–4. It validates the ID and version, reads the single scoped checkpoint row, and reads retained history evidence. Version 4 also probes the history archive columns. It has no catalog check for an existing store. [Open](../macos/core/Sources/RemozioCore/ContinuityStore.swift#L31-L81), [checkpoint row](../macos/core/Sources/RemozioCore/ContinuityStore.swift#L309-L319).

## Proposed admission check

Under the existing lease, inspect the complete `main.sqlite_schema` catalog. Match the exact expected objects for the store's reported version and feature tier. Require ordinary tables and the declared indexes, including the constraints that produce SQLite's internal indexes. Refuse all triggers and views, extra or missing tables or indexes, and unexpected table or index definitions. Do not blanket-exempt objects by name prefix. Gateway creates explicit indexes and has a partial index. SQLite also represents virtual tables as catalog entries of type `table`. [Gateway schema](../macos/core/Sources/RemozioCore/GatewayDatabase.swift#L994-L1009), [SQLite schema table](https://www.sqlite.org/schematab.html).

Reuse the existing table and migration definitions to specify accepted shapes. Include exact column metadata, keys, constraints, and index definitions. Use parsed metadata where it expresses the full definition and pin any remaining definitions to trusted, checked-in DDL. Account for reviewed differences from historical `ALTER TABLE` paths. Never execute schema text from the store being checked. The preparation store supplies a precedent for checking object kinds and names. Its tables-only rule needs an index allowlist for these stores. [Preparation catalog](../macos/core/Sources/RemozioCore/PreparationIntentStore.swift#L7405-L7422), [SQLite column metadata](https://www.sqlite.org/pragma.html#pragma_table_xinfo).

Check existing files before querying application rows, switching the journal mode, or starting cleanup. On journal format 19, first validate the allowed object kinds and tier-table definition, then read the tier and require its exact shape. Validate each supported migration source in the same transaction before changes, and check the destination before commit. Include journal legacy 1–11 only on explicit migration, ordinary 12–18, and format 19 by tier. Cover Gateway 1–3 only on legacy migration and 4–5 on current open. Cover Continuity 1–4, whose history columns and archive arrive in separate transitions. Preserve the existing initialization, scope, and checkpoint checks. Keep continuity digest bytes stable for accepted stores. [Journal migration](../macos/core/Sources/RemozioCore/JournalDatabase.swift#L399-L417), [journal tier](../macos/core/Sources/RemozioCore/AuthorityJournalSchema.swift#L20-L34), [Continuity migrations](../macos/core/Sources/RemozioCore/ContinuityStore.swift#L110-L124), [candidate column](../macos/core/Sources/RemozioCore/ContinuityStore.swift#L139-L153), [history archive](../macos/core/Sources/RemozioCore/ContinuityStore.swift#L167-L195).

## Existing files and verification

- Reject a schema mismatch with each store's `.incompatibleStore` error. Close the connection and release the lease. Leave the existing file available for operator inspection and authenticated recovery. Refusal must precede application writes, migration, cleanup, and use as health or continuity evidence. Keep current errors for scope, I/O, and hot-journal recovery.
- For each store, initialize a valid fixture and close it. Reopen with a harmless extra trigger, view, table, or index. Also cover an expected object with the wrong kind or definition. Assert the typed error, unchanged bytes on closed clean fixtures, no startup writes, and lease reacquisition. Include read-only cutover and Gateway health.
- Run the store suites and their migration and recovery coverage. Exercise the accepted version paths from native creation and migration fixtures. Compare journal digests, Gateway head and receipts, and Continuity committed and pending state before and after reopen. Preserve existing fault-injection tests. Some Continuity tests reopen while a test trigger is present. Remove that fixture trigger before reopening, after recording the failed write, and retain the durability assertions. [Journal rollback](../macos/core/Tests/RemozioCoreTests/JournalDatabaseTests.swift#L501-L513), [Gateway migration](../macos/core/Tests/RemozioCoreTests/GatewayDatabaseTests.swift#L891-L906), [Continuity rollback and reopen](../macos/core/Tests/RemozioCoreTests/ContinuityStoreTests.swift#L227-L260), [cutover](../macos/core/Tests/RemozioCoreTests/AuthorityJournalCutoverInspectionTests.swift#L120), [Gateway health](../macos/core/Tests/RemozioCoreTests/MachineUpdateGatewayHealthOwnerTests.swift#L77-L86).
