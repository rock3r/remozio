# Retain shutdown signals during daemon startup

Design for [#864](https://github.com/rock3r/remozio/issues/864), based on main `062e9ad509e6af7eeb006e9f0426d423de00a51b`. The findings are from source review.

## Affected entry points

For all seven signal-source sites, the loss window begins at the corresponding `SIG_IGN` call and ends when the underlying source registers. Source registration completes asynchronously after resume. A signal in the gap can leave no shutdown request for the worker. A signal before daemon signal setup can still take the default termination path. [Darwin signal disposition](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/sigaction.2.html), [Dispatch registration](https://developer.apple.com/documentation/dispatch/dispatch_source_set_registration_handler).

## Proposed startup and handoff

Install a shared, process-wide `sigaction` ingress synchronously as the first daemon startup action. Select the Setup service mode before this step so the one-shot commands keep their current behavior. Cover both SIGTERM and SIGINT. Use a small native handler that sets a lock-free stop latch and, once attached, wakes the consumer through a nonblocking close-on-exec pipe. Keep the handler limited to signal-safe operations. Its descriptor lifetime extends through process exit. An early request remains latched while the pipe and consumer are set up. A later request writes to the pipe even if its dispatch reader is still registering. This covers the application startup window from handler installation onward. [Darwin signal handling](https://developer.apple.com/library/archive/documentation/System/Conceptual/ManPages_iPhoneOS/man2/sigaction.2.html).

Serialize stop delivery with worker binding. Check the latch before configuring services or starting a worker. If startup already owns resources, cancel its worker, prevent further admission, and await the existing close or retirement path before returning success. Recheck after startup suspensions and before publishing a listener. Duplicate signals request the same stop. Keep the cleanup owner alive until its join completes and preserve its existing error reporting.

Keep the installed account job policy in this PR. The manifest sets `KeepAlive` unconditionally. The restart behavior after a configuration failure and launchd's escalation timing remain separate observations for an attended check. [Installed job](../macos/core/Sources/RemozioCore/InstalledAccountJobManifest.swift#L56-L67), [Apple launchd job guide](https://developer.apple.com/library/archive/documentation/MacOSX/Conceptual/BPSystemStartup/Chapters/CreatingLaunchdJobs.html).

## Verification

Use an unprivileged child that links the same ingress and startup coordinator. Add a barrier after handler installation and before worker binding, then another after a fixture has acquired its resource but before readiness. The parent signals only the child PID and holds the barrier until the native latch or pipe records arrival. The first case must exit normally with zero service starts. The second must close admission, cancel once, await the fixture's drain, and exit normally without publishing readiness.

Repeat with SIGINT, a duplicate signal during cleanup, and normal startup followed by SIGTERM. Assert exit status, order and count of lifecycle events, and resource release. Use a bounded wait and reap the exact child, following the existing process fixtures. Compile all four entry points. The installed launchd reproduction and real owner drain remain for an attended run. [Subprocess fixture](../macos/core/Tests/RemozioCoreTests/CommandProcessTests.swift#L393-L407).
