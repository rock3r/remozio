# Preserve storage failures from authority journals

[Issue #863](https://github.com/rock3r/remozio/issues/863) · Source review of `062e9ad509e6af7eeb006e9f0426d423de00a51b`

## Where the errors get lost

The issue names line numbers from an older commit. The current call sites below either collapse the SQLite result of a step or catch an error from another journal read and replace it.

| Store and operation | Current mapping |
| --- | --- |
| Routing state and operation count | Any result besides `SQLITE_ROW` becomes `RoutingJournalError.corruptData`. The state row is mandatory, and a count query also expects a row. The operation lookup already preserves unexpected SQLite results as storage failures. [State read](../macos/core/Sources/RemozioCore/RoutingJournal.swift#L61-L67) · [Count](../macos/core/Sources/RemozioCore/RoutingJournal.swift#L115-L119) · [Operation lookup](../macos/core/Sources/RemozioCore/RoutingJournal.swift#L132-L145) |
| Gateway registration and head | The registration lookup maps every non-row result to `.unconfigured`. The head count and latest-entry read map failed steps to `.corruptData`. The identity mismatch on a returned row already has a separate `.wrongScope` branch. [Registration and head](../macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L544-L564) |
| Gateway candidate and renewal | A non-row candidate step becomes `.wrongScope`. The renewal lookup combines the step result with a missing or unusable registration entry and reports `.unconfigured`. The candidate's activation lookup accepts `DONE` for no activation, then conflates a failed follow-up step with an unexpected second row. [Candidate lookup](../macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L933-L944) · [Renewal](../macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L751-L769) · [Activation](../macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L959-L970) |
| Gateway counts and retained enrollment | Failed steps become `.corruptData` in the initial empty-store count, pending-recovery count, retained enrollment lookup, capacity count and submission-history probe. The last probe expects `DONE` because the query has `LIMIT 0`. [Setup count](../macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L525-L541) · [Pending read](../macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L801-L808) · [Enrollment lookup](../macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L1073-L1080) · [Capacity](../macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L1083-L1115) · [History probe](../macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L1141-L1153) |
| Enrollment snapshot and restricted phones | The outer policy step already reserves `DONE` for `.unconfigured`. The snapshot's broad catch turns failures from `restrictedPhones()` and `all()` into `.corruptData`. The restricted-phone loop also combines a failed step with the row limit. [Snapshot and child reads](../macos/core/Sources/RemozioCore/EnrollmentJournal.swift#L268-L319) |
| Enrollment count and identity reuse | The scalar helper maps every non-row result to `.corruptData`. The revocation count in enrollment insertion maps a failed step to `.reusedIdentity`, the same outcome it gives an actual retained revocation. [Scalar and preparation](../macos/core/Sources/RemozioCore/EnrollmentJournal.swift#L432-L455) · [Revocation count](../macos/core/Sources/RemozioCore/EnrollmentJournal.swift#L365-L379) |

These paths can lose `BUSY` or `LOCKED`, primary or extended `IOERR`, `FULL`, `CANTOPEN`, `READONLY`, `INTERRUPT` and other SQLite errors. The same guard also discards the distinction when SQLite explicitly reports `CORRUPT` or `NOTADB`. The examples describe control flow, with no claim that every code occurs at every statement on the deployed SQLite version. [SQLite result codes](https://www.sqlite.org/rescode.html) · [SQLite step contract](https://www.sqlite.org/c3ref/step.html)

## Where that changes behavior

- The three transaction wrappers set `failed` on error. Each also sets `headMismatch` for its store's `.corruptData`. The latter retires the database during rollback and can retire the request owner. An I/O error that reached this path under a data-integrity label can therefore stop an otherwise reusable owner. [Enrollment wrapper](../macos/core/Sources/RemozioCore/JournalDatabase.swift#L828-L845) · [Routing wrapper](../macos/core/Sources/RemozioCore/JournalDatabase.swift#L1165-L1178) · [Gateway wrapper](../macos/core/Sources/RemozioCore/JournalDatabase.swift#L1238-L1247) · [Rollback](../macos/core/Sources/RemozioCore/JournalDatabase.swift#L168-L193) · [Request owner](../macos/core/Sources/RemozioCore/AuthorityJournal.swift#L1036-L1057)
- Gateway revocation status handles `.wrongScope` and `.unconfigured` as gateway blocked. A collapsed read failure can therefore look like a durable configuration problem. During admission, existing typed storage failures already project to `.storageUnavailable`. The authority still needs a successful read that proves no reservation before it can issue a retryable refusal. [Revocation status](../macos/core/Sources/RemozioCore/AuthorityPairingSetup.swift#L425-L450) · [Admission mapping](../macos/core/Sources/RemozioCore/ApprovalRequestCoordinator.swift#L559-L568) · [Reservation proof](../macos/core/Sources/RemozioCore/AuthorityJournal.swift#L708-L729)
- Presence already distinguishes genuinely absent client metadata from an unavailable connection. It clears the current status and disables mode controls on disconnect. A lost mutation reply triggers a status refresh. The app currently has no typed diagnosis for the underlying database failure on that transport path. [Presence state and mutation](../macos/app/App/PresenceControls.swift#L20-L32) · [Refresh and disabled controls](../macos/app/App/PresenceControls.swift#L42-L119)

## Proposed classification

Capture the SQLite result at the failing call, before another statement, finalization, or rollback. Preserve its extended value when available. Use the low byte only to choose the primary category. Keep positive `ROW` and `DONE` outcomes in the statement's own contract. Split nested reads out of broad decoding catches, or rethrow typed storage and database integrity errors before translating a local decode failure. [SQLite primary and extended codes](https://www.sqlite.org/rescode.html#primary_result_codes_versus_extended_result_codes) · [Error code lifetime](https://www.sqlite.org/c3ref/errcode.html)

| Evidence | Typed outcome and user-visible meaning |
| --- | --- |
| `ROW` with valid result | Return the actual state. Keep all identity, signature, capacity and consistency checks. |
| `DONE` where the schema permits no matching row | Keep the existing specific absence result. Use “Not configured” only for proven missing configuration. Keep a proven identity mismatch distinct. `DONE` for a required state row or scalar yields an invalid stored record, with no fabricated default. |
| `BUSY`, `LOCKED`, `IOERR`, `FULL`, `CANTOPEN`, `READONLY` and other SQLite failures | Preserve `JournalDatabaseError.storage(code)`. Classify `IOERR` as I/O, busy/locked as contention and full/read-only/open failures by their actual cause. Present “Storage is unavailable” and use a more specific action when the category proves one, such as freeing space for `FULL`. Use the existing temporary startup class for failures already treated as recoverable. Keep canceled work canceled. |
| A protected file operation returns an OS error | Keep `JournalLeaseError.system(errno)` as the separate typed I/O failure. For example, `EIO` and `ENOSPC` are operational failures. `EACCES` or `EPERM` may require a permissions check. A missing protected file in an installed store stops access. It does not establish that the account is unconfigured. Preserve metadata and identity failures. |
| SQLite returns `CORRUPT` or `NOTADB` | Use a distinct database-integrity error that retains the SQLite code. Present “Authority storage requires repair.” Retire through the existing integrity boundary and offer the supported recovery flow. |
| SQLite returns a row with a malformed payload, bad binding or inconsistent revision | Keep the existing domain invariant error and fail closed. Report invalid stored data or scope as appropriate. This establishes a record or identity problem rather than physical SQLite corruption. |

Apply the shared SQLite classifier to the failed step paths above and to their existing prepare, bind and completion helpers where those return a failure. The existing startup classifier already masks extended codes for temporary failures. Feed the new database-integrity case into repair diagnostics and keep permanent provisioning or lease errors distinct. Include the bounded phase and numeric code in diagnostics. Keep SQL values, protected paths, credentials and registration identifiers out of user-visible messages. [Lease error types](../macos/core/Sources/RemozioCore/ProtectedJournalLease.swift#L4-L7) · [Database error type](../macos/core/Sources/RemozioCore/JournalDatabase.swift#L5-L8) · [Startup classifier](../macos/core/Sources/RemozioCore/AuthorityStartupFailure.swift#L8-L26) · [Service messages](../macos/app/Authority/AuthorityMain.swift#L76-L94)

## Recovery and retry

- Keep a failed transaction marked failed even when its caller catches the error. Roll back through the current owner. A retryable read or a fresh transaction may use the same owner after successful rollback and lease validation. Keep the existing retirement cases for failed commit, failed rollback, automatic rollback of a write, epoch creation, and lost lease or integrity. Keep the separate trust and continuity validation rules, where only contention can preserve a live request owner. Keep the original failure available for diagnostics. [Transaction boundary](../macos/core/Sources/RemozioCore/JournalDatabase.swift#L168-L193) · [Owner retirement rule](../macos/core/Sources/RemozioCore/AuthorityJournal.swift#L1044-L1057)
- Reuse the capped startup backoff for classified temporary failures. Recover from disk space, permission or read-only failures only after the condition changes. An already retired runtime stays retired until the existing lifecycle opens and validates a new owner. Confirmed corruption goes to repair, with admission closed and files retained. Classification itself performs no repair, reset, deletion or re-pair. [Startup runner](../macos/core/Sources/RemozioCore/AuthorityServiceRunner.swift#L125-L154) · [Runtime runner](../macos/core/Sources/RemozioCore/AuthorityRuntimeRunner.swift#L175-L193)
- Keep automatic retries at boundaries that can prove an operation did not take effect. For command admission, preserve the reservation check and authenticated refusal. On a lost reply or unknown commit, return uncertainty and use the existing status or receipt lookup. For routing and gateway, refresh state and resume from the verified revision or operation receipt. The read error grants no right to replay a write, issue a new approval, replace enrollment, or rotate a token. Keep generic unavailable messaging on clients that did not receive a typed result. [Command retry gate](../macos/core/Sources/RemozioCore/CommandCallerReadiness.swift#L130-L146) · [Routing receipt reconciliation](../macos/core/Sources/RemozioCore/ApprovalRequestCoordinator.swift#L795-L842) · [Gateway retained-state renewal](../macos/core/Sources/RemozioCore/AuthorityPhonePushRegistration.swift#L88-L110)

## Tests

- Inject return codes at the specific statement step in temporary journal fixtures. Cover routing state and count, gateway head and candidate, gateway activation's first and trailing step, and enrollment scalar and nested snapshot reads. Inject `IOERR_READ` or `IOERR_FSYNC`, `BUSY` or `LOCKED`, `FULL`, `CORRUPT` and `NOTADB`. Check the exact returned category and original code. A scoped fixture seam should inject the result before any row decoding. It should not create a production fault switch. [Routing fixtures](../macos/core/Tests/RemozioCoreTests/RoutingJournalTests.swift) · [Gateway fixtures](../macos/core/Tests/RemozioCoreTests/GatewayAuthorityJournalTests.swift) · [Enrollment fixtures](../macos/core/Tests/RemozioCoreTests/EnrollmentJournalTests.swift)
- Exercise true absence, valid zero counts, missing mandatory rows, returned wrong scope, malformed payloads and duplicate activation rows. Inject a fault on a later step of a list and check that the caller receives an error instead of a partial success. Verify that an extended `IOERR` result remains an I/O failure.
- Check that recoverable failures abort the transaction, leave rows and revisions unchanged, and allow the next validated read on the same owner. Exercise a swallowed error, failed commit, automatic rollback of a write and lost lease. Verify that retirement still happens for genuine integrity failures. Prefer fixture injection after a valid open so the tests also work with the protected catalog checks proposed in [#995](https://github.com/rock3r/remozio/pull/995). [Transaction fixtures](../macos/core/Tests/RemozioCoreTests/JournalDatabaseTests.swift#L457-L525)
- Inject POSIX `EIO`, `ENOSPC` and access errors at the protected file boundary. Check startup status, capped retry only for temporary classes, and repair status for database corruption. Verify that gateway blocked and not configured remain specific outcomes. Verify that failed reservation proof and an uncertain commit produce no automatic replay.
