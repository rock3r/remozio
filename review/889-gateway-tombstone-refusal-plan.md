# Distinguish a gateway tombstone refusal from a lost reply

Refs #889 and #888. Base `0f43ab1a2ca572d79901593c2e0de57c889a6383`. This plan is for review.

## Defect

- The authenticated Gateway endpoint replies with `nil` when a command throws. The tombstone command returns bytes only on success. The Root channel converts `nil` to `.rejected`, which carries no evidence of a refusal. [GatewayXPCEndpoint.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayXPCEndpoint.swift#L68-L94), [GatewayService.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayService.swift#L52-L59), [GatewayRootChannel.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayRootChannel.swift#L145-L156), [GatewayRootChannel.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayRootChannel.swift#L215-L228)
- The publisher correctly reports an empty tombstone reply as inconclusive. The command might have committed before the reply was lost. The journal retains the original signed retirement and its first-unconfirmed time. A verified head or retained history must settle the barrier before later controls can proceed. [AuthorityWakePublisher.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/AuthorityWakePublisher.swift#L335-L388), [GatewayAuthorityJournal.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L460-L493), [GatewayAuthorityJournal.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L682-L705)

## First PR — Optional command and authenticated result

1. Reserve a distinct tombstone-result capability probe through the existing authenticated `head` path. Check the active synchronized registration and bind the result to the Root connection and its current registration. Invalidate that capability on failed synchronization, registration or key changes, or channel closure. A new Root with an old Gateway continues to send the original tombstone command when the existing tombstone capability is present. An old Root on a new Gateway sends its original commands and gets the same success or `nil` replies. Keep the existing hello versions and original opcode. Use a new opcode only on the negotiated path. [GatewayRootCommand.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayRootCommand.swift#L6-L39), [GatewayRootCommand.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayRootCommand.swift#L54-L86), [GatewayRootChannel.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayRootChannel.swift#L97-L138), [GatewayService.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayService.swift#L27-L43)
2. The new command carries the same exact Root-signed tombstone and expected predecessor, plus a fresh 32-byte request nonce. Success returns the existing receipt. The alternative reply carries a small allowlisted refusal code, the canonical registration, digest of the exact tombstone payload and Root signature, operation ID, revision, predecessor and nonce. Sign it in a separate domain with the pinned Gateway signing key. Use exact field sets, lengths and bounded deterministic CBOR. The Root verifies the signature, request binding, live deadline and single outstanding operation before it accepts the refusal as evidence.
3. Start with one refusal, `control_capacity_exceeded`. Create it only at the existing capacity decision inside the write transaction after authentication, predecessor and duplicate checks. Return it only after that transaction and the existing current lease checks succeed, before sending the result. A repeated identical successful tombstone still returns its existing receipt. Conflicting history, head races, authentication errors, interruption, SQLite failure, uncertainty during commit, and signing errors supply no proved refusal. The existing database layouts and control reserves stay in force. [GatewayDatabase.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayDatabase.swift#L449-L477), [GatewayDatabase.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayDatabase.swift#L723-L732), [GatewayDatabase.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayDatabase.swift#L968-L988), [GatewayDeliveryCoordinator.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayDeliveryCoordinator.swift#L241-L249)

This PR exposes the optional endpoint and tested channel methods. The running publisher keeps its current behavior until the second PR enables the capability.

## Second PR — Confirm the refusal and report health

1. Negotiate the new option alongside the current tombstone capability. On a verified refusal, issue one independent fresh signed head query through the existing query owner. Accept blocked status only if the head still proves the exact predecessor and matches retained local history. Recheck the active publisher session, lease, registration, trust revision and exact unresolved retirement under the current journal view. If the signed head has advanced, use the existing reconciliation path. A missing, expired, replayed or conflicting proof cannot set blocked status. An ambiguous mutation reply never triggers an immediate repeat through the legacy selector. [GatewayHeadReply.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayHeadReply.swift#L67-L91), [GatewayHeadReply.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayHeadReply.swift#L104-L126), [AuthorityWakePublisher.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/AuthorityWakePublisher.swift#L244-L269), [AuthorityWakePublisher.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/AuthorityWakePublisher.swift#L284-L296)
2. Record the confirmed refusal as owner-scoped gateway health for that exact pending control, bounded by the verified observation and live lease. Clear it on expiry, owner or registration change, or when signed history resolves the retirement. Reuse the existing `.blocked` health state for the Mac and add a fixed reason to the existing revocation diagnostic channel. The refusal neither acknowledges nor supersedes the retirement. Keep the original signed tombstone, its inconclusive age and the control ordering barrier. The journal can advance only on its existing verified evidence. [AuthorityGatewayRevocationState.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/AuthorityGatewayRevocationState.swift#L19-L61), [PairedPhoneManagement.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/PairedPhoneManagement.swift#L24-L47), [GatewayAuthorityJournal.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/core/Sources/RemozioCore/GatewayAuthorityJournal.swift#L498-L524), [PairingSheet.swift](https://github.com/rock3r/remozio/blob/0f43ab1a2ca572d79901593c2e0de57c889a6383/macos/app/App/PairingSheet.swift#L441-L456)

The split keeps the Gateway wire and storage review separate from the Root health decision. The new capability offers compatible rollout in both version directions. Existing phone, app status and Gateway control schemas retain their current formats.
