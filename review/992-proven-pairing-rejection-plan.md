# Prove a Root rejection of a pairing commit

Refs #992 and #859. Base `9cc16f105ecd3d37d1111a87a009c52e97ad14d2`. This plan is for review.

## Current behavior

- Root's commit selectors call the same operation. The common reply handler closes the endpoint and replies with `nil` on any thrown error. [AuthorityPairingXPCEndpoint.swift, line 381–418](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AuthorityPairingXPCEndpoint.swift#L381-L418)
- The channel validates the staged transcript, sends the selected commit, and expects a 64-byte signed receipt. Both a lost reply and a Root refusal enter the same error path. [AuthorityPairingChannel.swift, line 423–441](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AuthorityPairingChannel.swift#L423-L441)
- The Mac session records dispatch through `onSend`. After dispatch, it reports an unknown outcome for any thrown commit failure and blocks replacement until it can establish the outcome. [MacPairingSession.swift, line 357–400](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/MacPairingSession.swift#L357-L400), [MacPairingSession.swift, line 415–426](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/MacPairingSession.swift#L415-L426)
- The coordinator can commit enrollment, complete its checkpoint and then fail to retrieve or sign the receipt. The error type alone gives no proof that enrollment was refused. [ApprovalRequestCoordinator.swift, line 382–428](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/ApprovalRequestCoordinator.swift#L382-L428), [CheckpointedJournal.swift, line 22–67](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/CheckpointedJournal.swift#L22-L67)

## Proposed change

1. Offer version 6 through the existing versioned XPC compatibility hello. Root with installed pairing owners can answer 6. Current Roots cap the reply at 5, earlier Roots can answer 2, and the existing pre-submit reconnect covers Roots without the hello. Treat 3 through 5 as the current installed setup path with legacy commit replies. Keep the independent setup hello versions and their LAN and decision-proof requirements. Only enable the result selector on the authenticated connection generation that returned 6 and completed compatible setup. Reset the capability on reconnect. Keep the legacy selectors and replies for older apps and Roots. [AuthorityPairingChannel.swift, line 364–380](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AuthorityPairingChannel.swift#L364-L380), [AuthorityPairingXPCEndpoint.swift, line 143–158](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AuthorityPairingXPCEndpoint.swift#L143-L158)
2. Add one versioned XPC commit selector for the two existing proof shapes. Route it through the same exported invocation checks, operation admission and single-use staged attempt. Use a small bounded reply with either the existing signed receipt or one allowlisted rejection code and the exact setup ID and transcript digest. Verify the receipt as today. Accept a rejection only from the authenticated connection handling that invocation, with strict decoding and exact staged binding. Unknown code, invalid size, stale or mismatched binding, and missing replies remain ambiguous. This reply stays local to XPC. [AuthorityPairingXPCEndpoint.swift, line 391–418](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AuthorityPairingXPCEndpoint.swift#L391-L418), [AuthorityPairingXPCEndpoint.swift, line 420–450](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AuthorityPairingXPCEndpoint.swift#L420-L450), [AuthorityPairingChannel.swift, line 77–97](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AuthorityPairingChannel.swift#L77-L97)
3. Start with one code for expiry on an ordinary first enrollment. Match the staged ID and digest and check the proof shape in the existing Root operation. Before entry to the enrollment write, only an explicit zero from the existing sleep-inclusive attempt lifetime can produce this code. Use the same clock and attempt bounds as commit. Clock failure or invalid epoch, a missing attempt, invalid caller or proof, and any error from the enrollment write or receipt path use the existing ambiguous result. Keep re-pair expiry and its durable stage cleanup on the current path. Keep the in-transaction authorization, transport, proof, and deadline checks. Root can lose the refusal reply and the client must still handle that case as unknown. [AuthorityPairingSetup.swift, line 404–427](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AuthorityPairingSetup.swift#L404-L427), [PairingEnrollmentAttempt.swift, line 79–91](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/PairingEnrollmentAttempt.swift#L79-L91), [ApprovalRequestCoordinator.swift, line 392–428](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/ApprovalRequestCoordinator.swift#L392-L428)
4. Surface verified expiry through the Mac session and existing localized expiry UI. Retain the in-flight dispatch marker until the operation and cleanup drain. After verified refusal and drain, allow the user to start a fresh setup. Ambiguous results continue to require receipt reconciliation. Each dispatch can execute only once. Keep the distinction between Root registration and delivery of the receipt to the phone. [MacPairingSession.swift, line 360–401](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/MacPairingSession.swift#L360-L401), [PairingSheet.swift, line 393–400](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/app/App/PairingSheet.swift#L393-L400)

The app retains the #859 sleep-inclusive timeout and the existing pre-dispatch classification. The Android and LAN exchanges, signed receipt format, enrollment journal schema and receipt recovery protocol retain their current contracts.
