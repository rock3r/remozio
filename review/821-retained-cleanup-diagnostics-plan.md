# Report retained cleanup failures during Setup shutdown

Refs #821. Base `9cc16f105ecd3d37d1111a87a009c52e97ad14d2`. This plan is for review.

## Defect

- An endpoint hands off its invocation at [AdministrativeSetupXPCEndpoint.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AdministrativeSetupXPCEndpoint.swift#L183-L195). The cleanup owner retains it before calling `close()`. The catch reduces every error to `closed = false`. Its retry loop reports only whether the pending set is empty. [SetupAuditUpgradeCleanupOwner.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/SetupAuditUpgradeCleanupOwner.swift#L8-L34)
- Direct shutdown retries every 50 ms before it can release the Setup owner. Recovery shutdown turns the same cleanup failure into `.pending`. Both branches hold the placement and process leases while cleanup remains unsettled. [SetupAccountOwner.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/SetupAccountOwner.swift#L165-L197), [AdministrativeSetupShutdown.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AdministrativeSetupShutdown.swift#L314-L325), [AdministrativeSetupShutdown.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AdministrativeSetupShutdown.swift#L341-L365)
- Retirement retries after 250 ms. The native watchdog can end the process after 300 s with a generic message. That exit does not certify orderly closure. The cleanup reason is invisible during the wait. [AdministrativeSetupLifecycle.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AdministrativeSetupLifecycle.swift#L198-L217), [AdministrativeSetupLifecycle.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AdministrativeSetupLifecycle.swift#L407-L451), [SetupMain.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/app/Setup/SetupMain.swift#L58-L75)

## Bounded change

1. Store the latest redacted failure with each pending invocation. Set or replace the reason when that invocation's close attempt throws. Clear it only when the invocation leaves the pending set after successful cleanup. Reuse the existing `settling` guard and write both fields under its lock. Calling `close()` and reporting stay outside that lock. A competing retry leaves the latest completed result available while the other attempt runs.
2. Map known errors by exact typed case. Use `transaction_active` for the journal or preparation store's transaction-active case, `lease_busy` for the protected lease's busy case, `cleanup_unavailable` for the Setup or activation unavailable case, and `other` for the rest. Keep only the enum. Keep arbitrary error text, nested errors, paths, identifiers and payload fields outside both the snapshot and the log. [RuntimeAuditUpgradeOperation.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/RuntimeAuditUpgradeOperation.swift#L186-L199), [RuntimeAuditUpgradeCutoverCoordinator.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/RuntimeAuditUpgradeCutoverCoordinator.swift#L180-L191), [PreparationIntentStore.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/PreparationIntentStore.swift#L143-L146)
3. Report a snapshot when the existing direct or recovery shutdown retry finds a pending failure. Use the daemon's existing unified maintenance log pattern with a fixed event, fixed cause and count, for example `setup_shutdown_wait cleanup=audit_upgrade cause=transaction_active count=1`. Use at most one batch per 30 s for a pending episode. Emit immediately at its start and use the latest reasons on the next report. If a cleanup is active and has never failed, the snapshot has no reason to report. Keep normal XPC admission retries quiet. [InstalledAuthorityCommandRegistration.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/InstalledAuthorityCommandRegistration.swift#L7-L17), [AdministrativeSetupXPCEndpoint.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Sources/RemozioCore/AdministrativeSetupXPCEndpoint.swift#L93-L123)
4. Keep the 50 ms direct retry, 250 ms retirement cadence, recovery join order and existing watchdog. Custody, both leases and closed admission continue until the existing settlement checks permit release. The diagnostic reads in-memory state and does not enter the journal, acquire rights, start a service, or perform repair.

This uses the maintenance log so the reason remains available during retirement without changing the Setup status protocol. Keep failures of the owner close itself distinct from retained invocation failures.

## Tests

- Extend `SetupAuditUpgradeInvocationTests` with deterministic close failures. Verify the recorded reason survives dropping the endpoint reference, updates on a different thrown cause, and clears after cleanup succeeds. Use an error with a sentinel path and secret and assert that output contains only the bounded code and count. Exercise a second retry during an in-flight close and verify the existing single ownership.
- Exercise direct and recovery-joined shutdown with the owned fixture. While cleanup fails, verify the reason is available, new admission stays closed and both leases remain held. Let the existing retry settle successfully and verify that both leases then release. Drive the reporting interval with an injected clock or recorder so the test adds no wall-clock wait.
- Re-run the existing retention, lease-release and retirement watchdog controls. Verify that reporting neither resets the watchdog nor changes the results published by the status lane. [SetupAuditUpgradeInvocationTests.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Tests/RemozioCoreTests/SetupAuditUpgradeInvocationTests.swift#L79-L157), [AdministrativeSetupLifecycleTests.swift](https://github.com/rock3r/remozio/blob/9cc16f105ecd3d37d1111a87a009c52e97ad14d2/macos/core/Tests/RemozioCoreTests/AdministrativeSetupLifecycleTests.swift#L524-L610)
